Cyber Threat Monitoring

Threat indicators and monitoring coverage.
Live telemetry not connected

Monitoring status

This is the initial indicator register, not a live intrusion-detection system. No attack counts or clean-security status are being fabricated. Indicators below remain unmonitored until trusted event logs and detection rules are connected.

Current coverage: Indicator catalogue installed; automated event collection and alerting are not connected.

Review cadence: Monthly security review, including these indicators.

1. Administrator identity and access

Watch for repeated failed logins, unusual sign-in locations or times, unexpected concurrent sessions, inactive administrator access, unexpected administrator creation, and role or permission changes.

Not yet monitored in dashboard

2. Database and API security

Watch for denied RLS operations, unauthorized write attempts, unusual read volume, suspicious RPC execution, SQL-injection patterns, and unexpected schema, policy or grant changes.

Not yet monitored in dashboard

3. Storefront and checkout security

Watch for bot-like traffic spikes, repeated path probing, suspected XSS or injection payloads, price or quantity mismatches, abnormal order bursts, and denial-of-service indicators.

Not yet monitored in dashboard

4. Storage and file security

Watch for unexpected uploads, disallowed file types, suspicious file sizes, unusual image replacement, deletion or download activity, and bucket or object-policy changes.

Not yet monitored in dashboard

5. GitHub and source-code integrity

Watch for unexpected commits to main, changes to authentication or authorization code, collaborator or token changes, workflow or deployment configuration changes, and exposed private credentials.

Not yet monitored in dashboard

Manual snapshot from the available rolling 24-hour Supabase log window. This is not a live counter and does not automatically refresh. Open Supabase Logs Explorer to inspect current events.

Log sources available: Edge Gateway, Auth, Auth Audit, Postgres, PgBouncer, PostgREST, Storage and Realtime.

Edge Gateway: 238 events; 1 HTTP 4xx response and 0 HTTP 5xx responses in the inspected sample.

Authentication: 1 invalid-credentials response (HTTP 400), consistent with the recent invalid-login test; 1 HTTP 500 on a user lookup reported as a cancelled request. The latter needs observation if it recurs.

Database: log entries included administrator-requested connection termination/restart messages and errors from unsuccessful schema-inspection queries. No evidence in this sample establishes malicious database activity.

Storage / PostgREST: log sources were present; no high-severity errors were returned by the targeted error query.

Separate security-advisor finding: leaked-password protection remains disabled on the current Free plan.

Interpretation: no confirmed compromise was identified in the inspected sample. This is not proof that no attack occurred. A single failed login is not a brute-force pattern, and a cancelled request is not automatically an attack.

Severity guide

Critical Confirmed unauthorized administrator access, exposed secret credentials, privilege escalation or data theft.

High Credible account compromise or suspicious database modification.

Medium Repeated access violations, abnormal traffic or suspicious uploads.

Low Isolated failed requests or routine scanning attempts.

Severity is based on evidence and impact. A suspicious signal is not automatically proof of compromise. Missing logs mean “not monitored”, not “no threats”.
